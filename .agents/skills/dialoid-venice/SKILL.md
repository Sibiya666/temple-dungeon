# Dialoid: Venice и передача иконок GPT

## Маршрут владельца

- Все **концепты** (персонажи, восхождения, окружение, UI и другие визуальные исследования) и все **задники** создавать через **Venice**.
- **Иконки затем подхватывает GPT**: использовать утверждённые референсы и предметные замены. Этот скилл определяет передачу; сам вызов GPT выполнять доступным инструментом генерации изображений.
- Не заменять Venice встроенным imagegen для концепта или задника. Доступность другого генератора не меняет выбранный сервис. Исключение — явное новое указание владельца для конкретной работы.
- Создание/обновление скилла не означает поручение запускать генерации. Соблюдать остановку работы владельцем.

## Найти действующий проект и инструменты

Сначала прочитать `AGENTS.md`, `docs/art/ART_DIRECTION.md` и профильный дизайн запрошенного объекта. Открыть утверждённые изображения из арт-гайда; одного текстового описания стиля недостаточно.

Использовать существующий **`spike-3d/tools/venice.ps1`**, а не искать веб-плагин или заново писать API-клиент. Скрипт и локальный `spike-3d/.env` исключены из git, поэтому в отдельном worktree их может не быть.

Если файл отсутствует в текущем checkout:
1. Получить основную рабочую копию через `git rev-parse --path-format=absolute --git-common-dir`: для обычного репозитория родитель общей `.git` — корень основной копии. Для иной структуры проверить `git worktree list --porcelain`, не угадывать путь.
2. Найти там скрипт и актуальный арт-гайд; читать их оттуда. Если локальный арт-гайд отсутствует или устарел, учитывать более новые явные решения владельца из основной копии.
3. Генерировать в явно заданный выходной каталог текущей задачи, не изменяя чужой checkout. Не копировать `.env` в worktree.

Скрипт сам читает `VENICE_API_KEY` из своего `spike-3d/.env`. Не выводить файл, ключ, заголовок Authorization или тело HTTP с секретами. Для проверки доступности достаточно существования файла; не печатать значения. Если инструмент/учётные данные отсутствуют, сообщить конкретный недостающий компонент. Браузер и другой сервис не являются автоматической заменой.

## Подготовить изображение

- Уточнить назначение по поручению: исследовательский концепт, референс для 3D, самостоятельный задник или вариант утверждённого оригинала.
- Для самостоятельных концептов и задников задавать собственные композицию, архитектуру и ракурс в общем художественном языке. Не превращать все окна в замену предмета в одной сцене.
- Для вариантов сохраняемого дизайна использовать **выбранный оригинал семейства**, а не предыдущую перегенерацию. Фиксировать лицо, силуэт, материалы и свет; менять только перечисленные элементы. Для производных бокового/заднего видов 3D использовать утверждённый фронт как геометрический эталон.
- Референс для 3D: отдельная фигура целиком, нейтральный фон, мягкий ровный свет, нужная ортографическая проекция/A-поза. Оружие отдельно и пустые руки нужны для конкретной задачи моделирования, а не для каждого художественного концепта. Профильный пример — `spike-3d/briefs/rogach-rubaka.md`.
- Не переносить ограничения Рогача (рога, копыта, запрет плаща и т. п.) на героя или UI.
- Сохранять промпт UTF-8 в отдельном файле до запроса. Выходной PNG — под новым именем; не перезаписывать утверждённый оригинал.

## Выполнить через скрипт

Проверенные в проекте модели: `seedream-v5-pro` для генерации и `seedream-v5-pro-edit` для правки по референсу. Это исходный рабочий выбор, а не гарантия текущего каталога. При ошибке модели не подменять её или сервис молча.

Параметры существующего скрипта:

| Режим | Параметры |
|---|---|
| generate | `-Mode generate -Model seedream-v5-pro -PromptFile <абсолютный TXT> -Seed 101 -Out <абсолютный PNG>`; при необходимости `-NegFile <абсолютный TXT>` |
| edit | `-Mode edit -Model seedream-v5-pro-edit -PromptFile <абсолютный TXT> -Image <абсолютный PNG оригинала> -Out <новый абсолютный PNG>` |

Пример с заранее разрешёнными абсолютными путями в переменных, запуск из PowerShell:

```powershell
& $veniceScript -Mode generate -Model seedream-v5-pro -PromptFile $promptFile -Seed 101 -Out $outputPng
```

```powershell
& $veniceScript -Mode edit -Model seedream-v5-pro-edit -PromptFile $promptFile -Image $referencePng -Out $outputPng
```

Текущий скрипт: generate = 1024×1024, PNG, safe_mode=true, hide_watermark=true; edit = aspect_ratio 1:1. Не обещать другой размер/формат без реального изменения инструмента. У generate передаётся только положительный Seed; 0 означает, что seed не отправлен, хотя метаданные записывают 0. У edit seed вообще не отправляется: не заявлять воспроизводимость по этому полю. Лимит промпта проверять для выбранной модели, не считать старый лимит 1500 символов универсальным.

Запускать только согласованное количество запросов в пределах действующего бюджета. После ошибки сначала проверить причину; если запрос мог уже обработаться, не повторять платный вызов вслепую. После полученного изображения оценить результат перед следующей итерацией; остановиться при неизвестной стоимости, лимите/авторизации или необходимости нового решения владельца.

## Проверить и передать

- Проверить PNG и соседний JSON; просмотреть само изображение. При `blurred=true` из `x-venice-is-blurred` результат не принимать. Если флаг отсутствует, не выдавать это за подтверждённое false.
- Сверить с утверждённым оригиналом, назначением и арт-гайдом: свет, силуэт, материалы, отсутствие общего шума/bloom. Концепт не считать готовой моделью или доказательством работы в игре.
- Сохранять PNG, TXT промпта, JSON модели/режима/даты/seed/исходника. Скрипт сохраняет промпт и метаданные рядом с PNG; дополнительно фиксировать смысловой путь референса и исследовательский статус при переносе.
- Пометка скрипта о некоммерческом исследовании отражает решение владельца от 2026-10-30, а не новую проверку актуальных условий сервиса. Не объявлять коммерческие права подтверждёнными.
- Показать изображения и пути; не подключать в runtime без соответствующего поручения.
- Для иконок передать GPT **утверждённый исходник**, конкретную предметную замену и сохраняемые свойства. Каждый вариант начинать от оригинала, без цепочки перерисовок, общих просьб «улучшить» и незапрошенной смены стиля. Проверять 64/32/24 px, навигацию также 16 px; рамки, числа и состояния остаются в UI.
