# Тренировочная комната: геймпад (приложение к плану 4, задача 13)

Решение владельца 2026-10-30: геймпад нужен **везде**, включая тренировочную комнату, её окна и экран боя. Клавиатура с мышью и геймпад — на равных, переключение на лету. Раскладку предложил куратор интерфейса `dialoid-ui-curator` (2026-10-30). Пункты с пометкой **[Владельцу]** ждут подтверждения; до ответа действует предложенный вариант.

## 0. Основа

Ввод переводится на действия InputMap: у каждого игрового действия две привязки — клавиша и кнопка геймпада. Сейчас клавиши зашиты в `CombatDriver.HandleKey` и `WindowHost.Specs`/`HandleKey`; второй параллельный код для геймпада не пишется.

## 1. Раскладка (названия Xbox)

**В комнате (фокус у боя)**

| Действие | Геймпад | Клавиатура и мышь |
|---|---|---|
| Движение | левый стик, аналог, относительно камеры; мертвая зона 0,2 по кругу; до 0,6 — шаг, дальше — бег | WASD / ЛКМ |
| Слоты 1–5 | X, A, B, Y, RT | 1–5 |
| Канал (Вихрь) | удержание той же кнопки; у RT нажато при 0,5, отпущено при 0,3 | удержание |
| Подойти к цели на ближний бой | LB | ЛКМ по манекену |
| Следующая цель (на «Рое») | RB | ЛКМ по фигуре |
| Зум камеры | правый стик вверх/вниз | колесо |
| Зум по умолчанию | R3 | средняя кнопка |
| Пассивки / Скиллы / Разбор / Измеритель **[Владельцу]** | D-pad ← / → / ↑ / ↓ (открыть и закрыть одним нажатием) | P / K / R / T |
| Остальные окна и выбор манекена | Menu (Start): фокус на верхнюю панель | C/N/B/M/L/G |
| Фокус между боем и окнами, не закрывая их | View (короткое нажатие) | — |
| LT | резерв | — |

**Окна**
- Окно с элементами управления (персонаж, пассивки, асцендант, скиллы, билды, разбор, симуляция, графики) с геймпада открывается сразу с фокусом. Журнал и измеритель — без фокуса: бой идет, кнопки идут в бой.
- Пока фокус в окне, все кнопки принадлежат окну: герой стоит, зажатый канал отпущен, ядро идет дальше.
- B — назад на один уровень (закрыть список или всплывашку); на верхнем уровне закрывает окно в фокусе (как Esc). Не осталось окон с фокусом — фокус возвращается в бой.
- LB/RB — по кругу между открытыми окнами; окно в фокусе выделено более яркой бронзовой рамкой.

## 2. Навигация внутри окон

- **Фокус:** `ui_up/down/left/right` — D-pad и левый стик (повтор через 0,35 с, затем 0,08 с); A = `ui_accept`, B = `ui_cancel`; недостающие привязки `ui_*` дописать. Всем интерактивным элементам `FocusMode = All`; видимая рамка фокуса (бронза/золото) стилем `focus` темы. Окно запоминает последний элемент с фокусом, иначе фокус на первом.
- **Подсказка по фокусу:** та же подсказка, что по наведению мыши, показывается на `focus_entered` (узлы дерева, строки разбора, слоты).
- **Прокрутка:** правый стик листает `ScrollContainer` окна в фокусе; у контейнеров `follow_focus = true`.
- **Дерево пассивок:** стик/D-pad — ближайший узел в направлении (конус ±50°, вес = расстояние × штраф за угол), камера дерева держит выбранный узел в кадре; A — взять/снять (ровно как клик); X — выбор атрибута (как ПКМ), всплывашка с фокусом на текущем, A — подтвердить, B — отмена; LT/RT — масштаб; правый стик — сдвиг; R3 — центрировать на выбранном.
- **Выпадающие списки:** A открывает, фокус на текущем пункте, A выбирает, B закрывает без изменений.
- **Ползунок уровня:** ←/→ — шаг 1 с ускорением при удержании; LT/RT — ±10.
- **Поле сида:** ←/→ — ±1, X — «Случайный сид», Y — «Сбросить». Ручной набор длинного сида — позже (экранная клавиатура) **[Владельцу]**.
- **Измеритель:** полосы в цепочке фокуса, A на полосе — разбор; режимы и сегменты — кнопки; сброс — Y, затем подтверждение с фокусом по умолчанию на «Отмена».
- **Журнал:** фильтры — переключатели в цепочке фокуса, правый стик — прокрутка, Y — к последней строке.
- **Графики:** переключатели серий в цепочке фокуса.
- **Строка подсказок кнопок** внизу окна (только в режиме геймпада), в стиле D4: «Ⓐ Взять  Ⓧ Атрибут  Ⓑ Назад  LB/RB Окна».

## 3. Переключение на лету

- Автозагрузка `InputDevice`: свойство `Active` (клавиатура+мышь / геймпад), сигнал `Changed`; смотрит события в `_Input`, ничего не поглощает. На геймпад: нажатие `InputEventJoypadButton` или `InputEventJoypadMotion` с |значение| > 0,35. На клавиатуру и мышь: нажатие клавиши, кнопка мыши или сдвиг мыши больше ~4 px. Номер устройства не важен.
- В режиме геймпада: курсор скрыт, подсветка под курсором снята, следование за зажатым курсором прервано; подписи «Пассивки P» → значок D-pad ←, цифры слотов → X/A/B/Y/RT; строка подсказок в окнах; рамка фокуса видна. Обратно на мышь — всё наоборот (рамка остается только у поля ввода). Без перезапуска и настроек.
- Значки: Xbox по умолчанию, набор Kenney Input Prompts (CC0, в учет `assets/LICENSES.md`); пока набора нет — текст «[A]».
- Слот, удерживаемый обоими устройствами, отпускается, когда отпущен на обоих.
- `Input.JoyConnectionChanged` (обработчик — публичный метод): отключение — отпустить слоты и каналы, обнулить движение, переключиться на клавиатуру и мышь, сообщение «Геймпад отключен»; подключение — сообщение «Геймпад подключен», переключение по первому нажатию.

## 4. Обязательно сейчас и позже

**Минимум приемки:** пункты 0–3 выше, кроме перечисленного ниже.

**Позже:** радиальное меню всех окон (удержание View), значки PlayStation, вибрация, переназначение кнопок, экранная клавиатура для сида, маркер по оси времени в графиках, подсказки слотов панели боя с геймпада, запоминание позиции окна, выбранной с геймпада.

## 5. Самопроверка без живого геймпада

Синтетические `InputEventJoypadButton { ButtonIndex, Pressed, Device = 0 }` и `InputEventJoypadMotion { Axis, AxisValue }`: для обработчиков — через `viewport.PushInput`; для опроса (`Input.GetVector`, `IsActionPressed`) — через `Input.ParseInputEvent` с `Input.UseAccumulatedInput = false` или `Input.FlushBufferedEvents()`.

1. **Полнота привязок:** у каждого игрового действия есть и клавиша, и кнопка; у каждого окна из `WindowHost.Specs` есть путь с геймпада.
2. **Бой:** X — слот 1 принят; RT 1,0 — канал начат, RT 0,0 — прекращен, при 0,4 дребезга нет; стик (0,8; 0) двигает как D; стик 0,1 не двигает; после отпускания герой стоит; LB подводит к цели; RB меняет цель и кольцо.
3. **Окна:** D-pad ← открывает «Пассивки», фокус внутри окна; пока фокус в окне, X не применяет скилл, канал отпущен; B закрывает, фокус в бою; LB/RB проходят открытые окна по кругу.
4. **Достижимость:** в каждом окне повторными `ui_down/ui_right` от первого элемента достигаются все видимые доступные `BaseButton`, `Range`, `OptionButton`, `LineEdit` — главный тест «нет действия только для мыши».
5. **Подсказка по фокусу** совпадает с подсказкой по наведению (узел дерева, строка разбора).
6. **Дерево:** стик вправо — ближайший узел справа; A меняет состояние как клик (сравнить снимки); X открывает выбор атрибута; LT/RT — масштаб в пределах; выбранный узел виден.
7. **Списки, ползунок, сид:** A, `ui_down`, A меняет пресет как мышь; ←/→ — уровень ±1; X меняет сид.
8. **Сброс измерителя:** Y — подтверждение, фокус на «Отмена», A на «Отмена» не сбрасывает.
9. **Переключение ввода:** кнопка геймпада — `Active = Gamepad`, курсор скрыт, на верхней панели нет буквы клавиши, на панели боя значки вместо цифр; сдвиг мыши 10 px — обратно; 1 px и стик 0,1 не переключают.
10. **Отключение:** обработчик (0, false) при зажатом канале — канал отпущен, движение ноль, режим клавиатуры и мыши, сообщение показано.
11. **Снимки в режиме геймпада** (рамка фокуса, значки, строка подсказок, длинные русские подписи не обрезаны) — для ревью `dialoid-ui-curator`.
