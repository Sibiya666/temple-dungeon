# Переносимый Venice-скрипт

Нужен PowerShell **7+** (`pwsh`), без сторонних модулей. Для реального запроса нужны собственный доступ к Venice, доступная модель, собственный API-ключ и согласованный бюджет. Скрипт читает только переменную **VENICE_API_KEY текущего процесса**. Файлы `.env`, чужие ключи и настройки Dialoid не используются. Не печатайте ключ, не сохраняйте его в промптах/репозитории; вводите через свой менеджер секретов или безопасный способ настройки окружения.

Из корня пакета сначала выполните офлайн-проверку:

```powershell
pwsh -NoProfile -File ./scripts/venice.ps1 -Mode generate -PromptFile ./examples/backgrounds/ascendancy.txt -Out ./output/concept-v1.png -Seed 101 -DryRun
pwsh -NoProfile -File ./scripts/venice.ps1 -Mode edit -PromptFile ./examples/backgrounds/ascendancy.txt -Image ./examples/reference/approved-ui.png -Out ./output/variant-v1.png -DryRun
```

Пути соответствуют файлам пакета; команды выполняются из его корня. `-DryRun` валидирует аргументы, UTF-8 промпт и структуру входного PNG, подготавливает запрос **без чтения ключа и без сети**, не создаёт выходных файлов. Печатает лишь краткую сводку, не промпт и не base64. Успех DryRun **не проверяет доступность API, модели, цену, баланс, права или качество**.

Реальный запрос выполняется той же командой **без `-DryRun`**, только после собственного разрешения на расходы. Автоматических повторов нет. После сетевого сбоя запрос мог уже обработаться: прежде нового запуска проверьте расход/историю в своём аккаунте. Скрипт не печатает исходные HTTP-ошибки/ответы.

- Модели по умолчанию: `seedream-v5-pro` / `seedream-v5-pro-edit`; `-Model` задаёт явную альтернативу. Это рабочие значения нашего исследовательского процесса, не обещание актуального каталога.
- Generate: 1024×1024 PNG, необязательные `-Seed` (положительный) и `-NegativePromptFile`. `Seed=0` не отправляется. Даже фиксированный seed не гарантирует идентичность сервиса.
- Edit: один входной PNG, аспект 1:1. Seed и negative prompt здесь не поддерживаются и явно отклоняются. Seed для edit не заявляется.
- Все изображения имеют новый `-Out *.png`. Существующий PNG, JSON или соответствующие `.rejected` файлы вызывают отказ до сети. Файлы записываются через CreateNew.
- Ответ проверяется по HTTP-статусу, Content-Type, PNG-сигнатуре, IHDR, границам чанков, наличию IDAT/IEND и квадратным размерам. Это структурная проверка, **не полный декодер PNG/CRC и не визуальная приёмка**. Вход для edit также только PNG.
- Рядом сохраняется JSON: промпт, модель, режим, дата UTC, относительная ссылка на референс внутри выходной папки либо только имя файла вне её, фактически отправленный seed и `seedSent`, размеры, blur-статус. Абсолютные локальные пути не записываются.
- Если blur-заголовка нет, статус `unknown`. При `blurred=true` — только `*.rejected.png/json`, статус `rejected_blurred` и ненулевой код выхода. Остальные результаты — `unreviewed`, не автоматически принятые.
- Коммерческие права, тариф и условия сервиса скрипт не подтверждает: `rightsStatus=not_verified`. Проверяйте их самостоятельно перед публикацией.

Скрипт проверен локально PowerShell 7.6.5: parser — 0 ошибок; 9/9 офлайн-проверок (generate/edit DryRun, отсутствующие промпт/изображение, существующие PNG/JSON, пустой промпт, неверный PNG, недопустимый seed для edit). Invoke-WebRequest был локально заблокирован в тестовом процессе: 0 вызовов, DryRun не создал PNG. В рамках подготовки этого пакета реальные API-вызовы не выполнялись.

## Контактный лист без генерации

На Windows с PowerShell7 запустите: `pwsh -NoProfile -File ./scripts/build-contact-sheet.ps1`. По умолчанию используются пять мастеров из `examples/stained-glass/masters`; результаты64/32/24 и лист сохраняются отдельно в `outputs/contact-sheet`. Это только механическое масштабирование, сеть не используется.
