# Иконки подобраны и подставлены

2026-10-31. Пользователь прямо попросил подключить иконки после инвентаризации. В ходе работы в общей папке появился новый CombatHudView: подключение к нему сделано отдельным файлом `game/Ui/Combat/CombatHudView.Icons.cs` и одним вызовом установки после Setup. Основной файл чужого HUD не переписывался; прочие параллельные изменения сохранены.

## Что работает

- Все 13 выбираемых скиллов имеют собственные живописные рисунки. Три триггерных скилла используют рисунки родителей. Встроенный image_gen создал 10 недостающих скиллов и зелье; предыдущие оригиналы переиспользованы.
- Иконки вставлены в выбор скиллов, заголовок дерева, ротацию, строки результата симуляции и события журнала. AilmentId имеет приоритет над SkillId в строке недуга; текст события остаётся виден.
- Все шесть типов урона имеют разные монохромные формы в результатах симуляции. Тип выбирается из ключа реальной строки DamageType, не по цвету или исходному рисунку скилла.
- Пассивные узлы, 217 узлов скиллов и узлы асцендантов используют общие символы по фактическим эффектам. Это категории, не 400 уникальных картин. Механические узлы обозначаются общей шестернёй; выбранный атрибут и цена узла остаются текстовыми значками поверх.
- Значки добавлены во вкладки, список асцендантов и два существующих именных предмета. Русские названия и порядок выбора сохранены.
- В боевом HUD пять слотов показывают реальные текущие рисунки. Клавиша и перезарядка находятся отдельной полной строкой сверху, рисунок 32 px по центру, название снизу. Исходный текст Button сохранён для доступности и диагностических проверок; его заменяет только отрисовка. Подсказки и обработчики ввода не заменены.
- Компактная строка живых эффектов показывает героя/цель, реальные стаки и время. Положительные эффекты имеют прямую рамку, отрицательные — рамку с выемками. Для 30 баффов используются общие символы брони, скорости, ресурса и других категорий; неизвестные остаются общей категорией плюс полным исходным текстом. Полный текст эффектов и команда View сохранены. Строка не читает и не опустошает Feed.

Ресурсы находятся в `game/Ui/Art/Icons` внутри `res://`: они попадут в экспорт без внешней папки assets. Каталог `GameIcons` кэширует текстуры и не подставляет чужую картинку для неизвестного skill/ailment ID. Исходники и промпты остаются отдельно; [provenance.md](provenance.md). Сторонние изображения, emoji, платные API и ключи не использовались.

## Проверка

Сначала опциональная сцена `res://Ui/Art/IconIntegrationCheck.tscn` завершалась ошибкой отсутствующего каталога. После подключения проверяет все 16 skill ID с алиасами, шесть недугов, шесть enum типов урона, зелье, оба класса в реальном селекторе, пустой слот и неизвестный ID. Проверяет соответствие слотов HUD и сохранность ссылки на состояние при смене раскладки.

Ревью обнаружило риск обрезания перезарядки боковой иконкой на геймпаде. Он воспроизведён проверкой ширины при реальной перезарядке Мерцания (`cooldown-red.log`), исправлен раздельными слоями и проверен повторно. Ширина верхней строки с клавишей и секундами теперь проверяется по метрикам шрифта.

- `dotnet build game/Dialoid.Game.csproj --no-restore`: 0 предупреждений, 0 ошибок.
- Проверка иконок: `ICON_INTEGRATION_OK`, код завершения 0; фактические кадры получены Vulkan на RX 6750 XT.
- Существующий selftest: 33/33, `SELFTEST PASSED`.
- Общая проверка нового UI: `TOWER_UI_PASSED`, обе раскладки и возвращение в лабораторию.
- Независимое ревью подключения и реальных снимков: APPROVE; обрезание таймера исправлено.

В этой sandbox-среде Godot при запуске пишет `Failed to read the root certificate store`; это сообщение среды, все перечисленные тесты завершаются с кодом 0. Проблем загрузки текстур/скриптов в итоговом прогоне нет.
