# Задачи и исполнители Dialoid

Решение владельца: чаты остаются для обсуждения идей и тестирования. Исполнение ведётся задачами и временными экземплярами трёх ролей Codex. Семь существующих кураторов выполняют независимое ревью.

## Карточка задачи

Для работы, которая требует нескольких шагов или передачи исполнителю, создай отдельный Markdown-файл рядом с этим документом. Короткая локальная правка не требует отдельной карточки.

```markdown
# TASK-<id>: название
Статус: ready | in_progress | review | done | blocked
Исполнитель: роль и id экземпляра (после запуска)
Цель: наблюдаемый результат
Основа: решения владельца, спецификации, актуальные эталоны
Зависимости: id задач или «нет»
Разрешённые файлы: конкретные файлы/папки
Не входит: границы задачи
Критерии готовности: проверяемые условия
Проверка: команды, игровые сценарии, необходимые кадры
Ревью: нужные кураторы
Результат: файлы, проверки, дефекты, ссылка на коммит при наличии
```

## Выполнение

Обязательный критерий задач, добавляющих навыки или узлы: собственные иконки автоматически входят в область работы. В карточке перечислять ID и соответствующие ассеты; до `done` создать, подключить и проверить все иконки в runtime и в 64/32/24 px, сохранить происхождение и игровой кадр, получить независимое UI/арт-ревью. Ранговое усиление тоже является узлом; один рисунок сохраняется на всех рангах этого узла. Заглушки, общие символы эффектов и повтор иконки навыка не засчитываются. Если ассеты ещё не готовы, задача контента остаётся незавершённой; отдельно завершённый этап раскладки не означает готовность изображений. Отдельного напоминания владельца для производства иконок не требуется. Канонические правила: `AGENTS.md` и `docs/art/ART_DIRECTION.md`.

1. Основной агент уточняет требования из обсуждения и назначает область файлов. Три роли — специализации, не лимит числа агентов. Каждый экземпляр получает собственную задачу и id.
2. Параллельны только независимые задачи. Два писателя не меняют один файл в общей рабочей копии. Рабочие копии изолируют изменения, но не устраняют смысловые конфликты и зависимости; их объединяет основной агент.
3. При обнаружении нужной правки за пределами области исполнитель описывает её основному агенту. Не расширяет область молча и не откатывает изменения соседей.
4. Общие манифесты, Main.cs, project.godot, учёт лицензий и интеграционные файлы принадлежат одному назначенному интегратору на время задачи. Исполнители передают необходимые дополнения.
5. Готовый результат включает реализацию и доказательства проверки. Статус review не равен done. Автор и независимый ревьюер — разные экземпляры.
6. Основной агент проверяет diff, собирает результаты, разбирает замечания и выполняет общую проверку после интеграции. Только после неё задача done. Существующие дефекты явно записываются.
7. Тестировщик запускается временно под сценарий из роли общего агента; постоянная четвёртая роль пока не нужна. Он проверяет сборку, регрессии, игру и кадры, не переписывает реализацию без назначения.
8. Коммиты и интеграция выполняются по действующему поручению, только своих файлов. Не создавай новые чаты для обычных подзадач; используй агентов внутри текущей работы.
9. Рутинные решения принимай сам в пределах задачи. Владелец нужен при реальном выборе продукта/стиля, отсутствии необходимых данных или новом расходе без согласованного бюджета. Не спрашивай повторно о разрешённом действии.

Определения ролей — `.codex/agents/`. Модель и права наследуются: роли не увеличивают разрешения и не закрепляют платную модель. Формат соответствует [документации Codex](https://learn.chatgpt.com/docs/agent-configuration/subagents).
