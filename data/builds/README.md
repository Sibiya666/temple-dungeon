# Эталонные билды

Демо-сборки для владельца и регрессионный набор баланса (§12, §15). Все шесть основных билдов — 60 уровень: 59 пассивок, асцендант с 4 notables, 5 слотов, скиллы 20 уровня со всеми 20 очками дерева. Keystones в основных билдах нет: для теста keystones (§15.6) собраны отдельные билды в `keystones/` (см. «Служебные билды»). Ротация — приоритетный список: первый доступный скилл, генераторы в конце. Спендер тратит ресурс, как только его хватает. Билды проверяет `core/Dialoid.Core.Tests/Content/ReferenceBuildTests.cs`, приемку баланса — `BalanceAcceptanceTests.cs`.

Основные билды — тематические: каждый держит свою идею (доминирующий скилл и тип урона). Поэтому они **не потолок класса**. Потолок лежит в `parity/` (см. ниже). Паритет классов (§15.10) считается по файлам `parity/` на всех трех уровнях.

## Воитель (двуручный топор)

- **`warrior_berserker_whirlwind` — «Кровавый Берсерк-Вихрь».** Вихрь на кровотечении, основной урон — физический. Ротация: Боевой клич → Рывок → Сокрушение → Вихрь, Метательный топор добирает Ярость. Асцендант: Неутолимый, Кровавый пир, Без оглядки, Вихрь ярости. Пассивки: кровавый кластер («Мясник», «Открытые раны», «Кровавая баня», «Безупречная техника», «Шквал ударов»), «Глас войны», «Железная воля». В дереве Вихря — «Неистовое вращение» и «Ураган клинков».
  - **Внимание:** с Вихрем ярости Вихрь нельзя ставить в ротации выше Сокрушения. Вихрь выше 50% Ярости ничего не стоит, поэтому канал не кончается, и остальные скиллы не применяются. Это не ошибка движка, а следствие приоритетной ротации.
- **`warrior_thunderer_crush` — «Громовержец Сокрушение».** Сокрушение, превращенное в молнию («Громовой молот»), с копией «Землетрясения». Ротация: Боевой клич → Рывок («Грозовой рывок») → Сокрушение → Вихрь, Рассекающий удар генерирует. Асцендант: Разряд, Цепной удар, Статический заряд, Буря в жилах. Пассивки: «Грозовой фронт», «Цепная реакция», «Неуемная ярость», кровавый кластер.
- **`warrior_fire_cleave_crit` — «Огненный Громовержец».** Огненный вариант Громовержца, а не чистый «Огненный клинок крит» из §12. Рассекающий удар в одну цель («Точный удар») с поджогом («Пылающие раны»), огненный Вихрь («Огненный смерч») и «Огненный след» Рывка. Рассекающий удар лидирует слабо: 29% против 25/24/22%. Асцендант: Разряд, Цепной удар, Заземление, Буря в жилах. Пассивки: «Испепеление», «Пекло», «Архимаг», «Безжалостный удар», «Убийца».
  - **Почему не «чистый» огненный клинок.** У Воителя нет асцендантской поддержки огня (вопрос владельцу). Берсерк держит Рассекающий удар выше следующего скилла в 1.25 раза только с notables, которые ничего не дают; Громовержец не поднимается выше ≈ 1.2.

## Чародей (посох)

Шесть скиллов на пять слотов, поэтому все три билда Чародея делят большую часть набора (Искра, Мерцание, Шаровая молния и Метеор есть во всех трех). Различие — в спендере-лидере, развилках деревьев и асценданте.

- **`sorcerer_pyromancer_fireball` — «Огненный шар + поджог, Пироман».** Огненный шар со «Сжатием», «Вечным пламенем» и «Пламенным кольцом». Метеор и Шаровая молния тоже огненные («Солнечный шар»). Ротация: Мерцание → Метеор → Шаровая молния → Огненный шар, Искра генерирует. Асцендант: Распространение, Пепел, Вечный огонь, Жар души. Пассивки: «Испепеление», «Пекло», «Архимаг», криты заклинаний.
- **`sorcerer_cryomancer_ice_lance` — «Ледяное копье, Криомант».** Ледяное копье на критах с пирсом («Сквозной холод», «Ледяной венец»), Метеор переведен в холод («Ледяной метеор»). Ротация: Мерцание → Метеор → Шаровая молния → Ледяное копье, Искра генерирует. Асцендант: Раскол, Ледяная броня, Хрупкость, Ледник. Пассивки: «Лютая стужа», «Ледяное сердце», «Чародейская точность», «Разящая мысль».
- **`sorcerer_spark_hybrid` — «Грозовой Криомант: Шаровая молния».** id файла сохранен из плана. На деле это билд Шаровой молнии: она дает 56%, Искра как генератор — 10%. Огня в билде нет. Ледяное копье («Ледяная глыба») дает 10% урона и замораживает. Ротация: Мерцание → Метеор → Шаровая молния → Ледяное копье, Искра генерирует. Асцендант: Раскол, Ледяная броня, Хрупкость, Ледник — у Чародея нет асцендантской поддержки молнии (вопрос владельцу), поэтому Ледник здесь — наполнитель вне темы (`OffThemeNotables` в тестах); Ледяная броня порог проходит.

## Известные более сильные сборки вне набора

- **Берсерк-Сокрушение** (`parity/warrior_l60`): 23229 тренировочный DPS, 20329 по рою, выживание 21 с. Потолок Воителя среди сборок, живущих ≥ 20 с. По цели поиска √(тренировочный × рой) он ×1.15 от лучшего эталона Воителя (тест `Class_ceiling_is_within_1_5x_of_the_best_reference`), по одной цели — ×1.70. Схема: Неутолимый + Без оглядки + Вихрь ярости + Рассечение плоти, Сокрушение 78% урона. Сокрушение на 100 Ярости платит здоровьем, и Ярость остается полной («Безумие»).
- **Чародей без темы** (`parity/sorcerer_l60`): 18346 тренировочный DPS (Огненный шар + Метеор) против 13010 у эталонного Пиромана.

## Служебные билды

- `parity/<класс>_l1.json`, `_l20.json`, `_l60.json` — сильнейшая найденная сборка класса на 1, 20 и 60 уровне: только тренировочный DPS, без темы и без keystones; на 20 и 60 уровне — выживание ≥ 20 с. По ним считается паритет (§15.10): на 1 уровне 33.5 против 29.1 (×1.15), на 20 — 3493 против 3453 (×1.01), на 60 — 23229 против 18346 (×1.27).
- `l20/<эталон>.json` — эталон 20 уровня (тот же рецепт, 19 пассивок, один notable). По ним калибруются манекены (§11.1) и проверяется скилл из лута.
- `keystones/<keystone>_fit.json` и `_unfit.json` — подходящая и неподходящая сборка для каждого keystone (§15.6). Keystone в них — лист пути, поэтому тест убирает только его. Большинство — эталон плюс кратчайший путь к keystone. Исключения: `avatar_of_fire_fit` — отдельный поиск вокруг Аватара (все пассивки огненные), потому что эталон с добавленным Аватаром получает лишь ×1.09; `inevitability_fit` — молниевый гибрид без крита; `stone_skin_unfit` — Пироман со всеми атрибутами в Ловкости (естественные билды Чародея от Каменной кожи не теряют, BALANCE_NOTES).
- `attributes/<класс>_no_attribute_nodes.json` — копия эталона (Воитель — `warrior_thunderer_crush`, Чародей — `sorcerer_pyromancer_fireball`). Каждый атрибутный узел, без которого билд остается связным, заменен соседним малым узлом; бюджет очков тот же (§15.9). Атрибутные узлы вокруг стартов и между ветками дерева остаются, потому что без них отваливается часть билда; поэтому тест §15.9 дополнительно подменяет каждый атрибутный узел эталона на месте (`Every_attribute_node_swapped_in_place_for_its_best_small_neighbour_changes_little`).

## Мертвые очки

В деревьях скиллов по 15–20 узлов, а очков 20, поэтому часть очков ничего не меняет (`BuildOptimizer.dll check <билд>`, «ZERO»):
- Боевой клич: «Звон в ушах» — во всех трех Воителях;
- Берсерк-Вихрь: «Бронированный натиск» (Рывок), «Широкий удар» и «Сотрясение» (Сокрушение), «Заточка» (Метательный топор);
- Громовержец: «Широкий круг» (Вихрь); «Рваные раны», «Кромка», «Удар грома» (Рассекающий удар — генератор, почти не бьет);
- Огненный Громовержец: «Быстрые ноги» (Рывок), «Широкий удар» и «Пик ярости» (Сокрушение);
- Криомант: «Остаточный образ», «Фазовый барьер» (Мерцание), «Ледяное крошево», «Воспламенение» (Метеор);
- молниевый Криомант: «Глубокий холод» (Мерцание), «Ледяной клин» (Ледяное копье), «Ледяное крошево», «Кратер», «Пепельная завеса» (Метеор);
- у Пиромана мертвых очков нет.

## Как билды получены

Билды собрал оптимизатор `tools/BuildOptimizer`, локальный поиск на симуляторе (заголовок `Program.cs` описывает его целиком). Рецепт каждого билда лежит в `tools/BuildOptimizer/rebuild_references.sh`. **Скрипт запускается один и последовательно** (по умолчанию): шаги keystones, вариантов атрибутов и 20 уровня читают файлы эталонов, которые переписывают другие прогоны. Полный прогон — около 3 часов.

Цель поиска — √(DPS на «Тренировочном» × DPS пака на «Рое»). Ее можно умножить на `(выживание / 180)^w` (`--survival-weight`); для текущего набора w = 0. Каждый эталон обязан жить ≥ 20 с (`--min-survival 20`), а каждый взятый notable асценданта эталона 60 уровня — давать ≥ 3% цели или снижать урон, полученный от «Атакующего босса» за 20 с, на ≥ 8% (`--asc-floor`; наполнители вне темы — `--asc-exempt`).

Ограничения (штрафы):
- каждый скилл ротации применяется хотя бы раз;
- доминирующий скилл архетипа дает урона не меньше чем в m раз больше любого другого;
- доминирующий тип урона не ниже заданной доли;
- запрет узлов, которые противоречат теме (например яд или чужая стихия);
- keystones запрещены.

Для билдов `parity/` используется только тренировочный DPS, без темы. После каждой итерации баланса набор пересобирается тем же скриптом; сводка всех метрик приемки — `BuildOptimizer.dll suite --all`, таблица сожалений notables — `BuildOptimizer.dll regret`.

## Загрузка и экспорт

Файл — это JSON билда в формате `BuildCodec.ToJson` (snake_case).

```csharp
var data = DataLoader.Load("data").Data!;
BuildCodec.TryFromJson(File.ReadAllText("data/builds/warrior_thunderer_crush.json"), data, out var build, out var error);
var code = BuildCodec.Export(build!);                      // строка «DLD1:…», ее можно переслать
BuildCodec.TryImport(code, data, out var copy, out error); // обратно в Build
File.WriteAllText("my_build.json", BuildCodec.ToJson(copy!));
```

В тестах билды загружает `ContentHarness.LoadBuild("warrior_thunderer_crush")`, путь указывается без `.json`. `TryFromJson` проверяет id. Законность билда проверяет `BuildRules.Validate`.
